## Decisions made by Claude (small, inside the documents)

- F1: Error body built by one global filter; code throws `ApiError(status, code, message, details?)`. Nest's own 404 (unknown route) maps to `NOT_FOUND`, its 400 to `VALIDATION_FAILED`, anything else to `500 INTERNAL_ERROR` (cause logged).
- F1: Prisma client generated by `postinstall` and `build` scripts.
- F2: Prisma creates `text[]` columns as nullable. Migration `array_columns_not_null` sets NOT NULL (DB v0.5). Prisma's diff ignores list nullability, so no drift. Add the same `ALTER ... SET NOT NULL` by hand for any new list column.
- F2: `apps/api/.prettierignore` skips the generated client, so `npm run format` in `apps/api` is safe.
- F3: Validation with `zod` through `ZodPipe` (`src/common/zod.pipe.ts`); `VALIDATION_FAILED` details are `{ fields }`. JWTs with `jose`, hashing with `@node-rs/argon2` (TDD 3).
- F3: Global `AuthGuard` (APP_GUARD); mark open routes with `@Public()`. The guard sets `req.userId` (type `AuthedRequest`).
- F5: Profile response omits `id` and `userId`. Repeated array values are rejected (400), not removed; `preferredStyles` is lowercased first. A color may be both liked and disliked (API v0.7, 3.5).
- F5: Optional-text helpers (`blankToNull`, `optionalText`) live in `src/profile/profile.controller.ts`; move them to `src/common/` when items need them.
- F6: `CloudinaryService` (`src/uploads/cloudinary.service.ts`, exported by `UploadsModule`) uses `fetch` + `node:crypto`, no SDK. Tested against the real account 2026-11-01: signed upload OK, tampered `public_id` rejected, destroy removes the file. A deleted file's URL can still load from the CDN cache for a while (no `invalidate`, accepted).
- F7: `src/ai/`: `TEXT_AI` token → `GeminiProvider` (exported by `AiModule`). `generateJson()` in `gemini.client.ts` does rotation and error mapping with one deadline per call; `rankOutfits` (feature 10) reuses it. `tagClothing` takes bytes (TDD v0.12); feature 8 adds `CloudinaryService.download()` (15 s, 404 → `INVALID_PUBLIC_ID`). `env()` helper in `src/common/env.ts`. Tested live 2026-11-01 with 2 keys.
- F8: Shared zod helpers and `uuidOr404()` live in `src/common/fields.ts` (moved from profile). `uniqueList` has no default, so `.partial()` PATCH schemas leave omitted fields unchanged; add `.default([])` where a full body needs it.
- F8: Public IDs must match `clocobi/{userId}/items/{original|clean}/<one segment>` exactly, so `../` cannot escape the folder (the URL parser would resolve it on download). `PATCH cleanPublicId` takes a string only (no clearing). Cloudinary download failures other than 404 (5xx, timeout) are `500 INTERNAL_ERROR`. Cloudinary deletes are awaited before the response (serverless may freeze after it). `GET /items/summary` counts in memory from one query (`shortcut:` comment).
- F8: Tested live 2026-11-01: sign, upload, analyze (about 4.3 s), create, list, summary, 409 on COMPLETE to DRAFT, delete (204, then 404).
- F10: Pure rules in `src/outfits/candidates.ts` (missing slots, candidates with R9 options, `comboKey`, sample, AD10 repair), unit-tested. Gemini `rankOutfits` uses aliases `i1..` for items and `c1..` for candidates; an unknown alias stays as is and the repair drops it. Each outfit is one Prisma `create` with nested `OutfitItem` rows (Prisma runs a nested write in one transaction), P2002 skipped. `MISSING_SLOTS` message lists the slots; `NO_NEW_COMBINATIONS` message is "Every outfit your wardrobe allows for this occasion already exists. Add items for new ones."
- F10/11: Tested live 2026-11-01 (7 items, 4 combinations): first generate 3 outfits in about 13 s, all with blazer and watch for a walk outside (R10); second generate 1 outfit with `FEWER_THAN_REQUESTED`. `gemini-3.6-flash` returned HTTP 503 "high demand" twice before that (mapped to `AI_FAILED`, as designed).
- F11: `DELETE /outfits/:id/items/:outfitItemId` uses `outfitItem.deleteMany` filtered through `outfit.userId` (DB D2). The outfit's `updatedAt` does not change when an optional item is removed.
- F12: `IMAGE_GEN` → `CloudflareProvider` (in `AiModule`); `generateOutfitImage` returns the image bytes (`Buffer`). Reference images are sent as multipart file parts `input_image_0..3`: the Cloudflare model page does not document the format (checked 2026-11-01), so confirm on the first live call. Quota mapping: 429 or an error message matching daily/allowance/neuron/quota (open item 14). Prompt and reference order in `src/outfits/image-prompt.ts`; all garments are described in the prompt, the first 4 also go as references. References: `cleanPublicId` else original, through `c_limit,w_500,h_500`. Backend upload `CloudinaryService.upload()` and the reference transformation tested live 2026-11-01 (333x500 result). Profile missing at image time → "a person".
- F12b: `generateSchema` (in `outfits.controller.ts`) uses `.prefault({})` so a missing body means no preference. Colors go into the Gemini data only when set. Migration written by hand (`prisma migrate dev` is interactive and fails in this shell), applied with `prisma migrate deploy`; diff shows no drift.
- S3: `/spike/bg-removal` (temporary, delete after the spike) runs the real resize (`src/lib/image.ts`, reused by feature 16) then `removeBackground` with model `isnet_fp16` (medium, default) or `isnet_quint8` (small) and device `cpu`/`gpu`; logs sizes and times; a URL box does the CORS fetch the "retry clean image" flow needs. `SPIKE_ISOLATE=true` adds COOP/COEP on `/spike/*` (read at `next dev` start or at build time). Added `@imgly/background-removal` 1.7.0 and its peer `onnxruntime-web` 1.21.0 (exact), and Vitest to `apps/web`. Webpack production build passes. Not run in a browser by Claude.
- S2/F12 live test 2026-11-01: one `POST /outfits/:id/image` with `flux-2-klein-4b` (3 references, originals) returned 200 in about 11 s; good image. Multipart file parts confirmed. klein-4b is about 95 to 125 neurons per image by the listed prices vs about 1,500 for klein-9b; `CF_IMAGE_MODEL` switched in `.env` and `.env.example`. Test data left in the Neon `dev` branch: 3 items (black t-shirt, chinos, sneakers), occasion "Coffee with friends", 1 outfit with an image.
- F3: Seed lives in `src/seed.ts` (compiled with the app) because Node cannot run the generated Prisma `.ts` client directly.
